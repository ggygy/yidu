# 11 · 视觉差距审计(v4 设计稿 vs v0.2.x 实现)

## 方法与局限

- **静态审计,没有实际运行。** 无法 `npm install`/`tauri dev`,也无法截屏。结论来自三类材料:
  1. v4 设计稿 `visual/exports-v4/*.png`(8 张,2880×1920 / 1110×1554,按 @2x 读,即逻辑 1440×960 / 420×640 左右);用 PIL 在稿上取了像素色值和字形高度(下文写「稿测」)。
  2. 用户实机截图:`1.png`(快捷窗·暗色·流式)、`2.png`(快捷窗·暗色·结果)、`3.webp`(主窗·暗色·空态 + 设置抽屉)。**三张截图都早于 commit e475da4**(截图中快捷窗头部是 `pl-16`、底行带「载入演示 ⚡」文字标签,而当前代码已改成 `pl-20`/「演示 ⚡」),所以截图里有几处问题当前代码已经改过,但**改动效果没有实机验证**,下文会单独注明。
  3. 实现代码:`app/src/styles.css`、`app/src/quick/main.tsx`、`app/src/main.tsx`、`app/src/md.tsx`、`app/src/reader.ts`、`app/src/dirselect.tsx`、`app/src/icons.tsx`、`app/src-tauri/tauri.conf.json`。
- 标「代码推断」的条目没有截图佐证,只是按 CSS/JSX 推出的渲染结果。原生红绿灯的位置按 macOS `titleBarStyle: Overlay` 的默认值估算(约 x 13–72pt、y 8–22pt),可能有几 pt 偏差。
- 稿件命名对照:`rq4hx` 主窗空态;`xI0WT` 阅读·对照·翻译中;`fg2Yk` 阅读 + 点词卡;`h9qRY` 文章库滑出;`YqF5t` 新建翻译;`j3gPX` 设置抽屉;`E5SaFa` 快捷窗亮·流式;`iNDzp` 快捷窗暗·流式。
- spec.md §6 写的视觉基准还是 **v3**(`exports-v3`),本审计按任务要求以 **v4** 为准,两份之间的差异不在本次范围内。
- 只记录事实,不给改法。严重度:高 = 一眼可见、损害识别度或可用性;中 = 明显偏离稿件或局部可读性问题;低 = 细节。
