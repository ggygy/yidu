## Question

用一组标准样例(多级标题、嵌套有序/无序列表、表格、引用嵌套、hr、围栏/缩进代码、HTML 块、链接/图片/行内码、纯文本软换行)做「原文 → 译文 md」往返原型,定:块模型如何改(列表/引用整体成块 vs 项级、表格校验、hr 保留、HTML 与缩进文本是否误判为代码)、非 md 粘贴输入的归一化规则、`<s>/<t>` 协议对源文中尖括号的转义、新增哪些译后校验项(标题级、列表标记、表格形状、行内码集合)、temperature 取值;验收标准为保真率指标 + 渲染对齐 GitHub 样式(与 09 渲染侧共用)。

## Answer

(2026-11-17)原型 [proto-md/roundtrip.mjs](../proto-md/roundtrip.mjs) + 结果 [04-md-fidelity.md](../research/04-md-fidelity.md):10 个样例上现行切块逐块渲染结构一致 **4/10**,提议方案 **10/10**;10 种模拟模型损伤,现行校验检出 **1/10**,结构签名 **10/10**(不经模型、真实损伤频率未测)。用户全部采纳推荐:

1. **块模型**:所有顶层节点都成块,不再丢弃(修 `---`、脚注、引用式链接定义被静默删除);**列表 / 引用 / 表格整体一块**翻译,超约 1200 字才按顶层项拆,拆开的项带 group,渲染时合回一个列表;块间保留原文分隔文本,拼回即原文结构。
2. **直通不译**:代码(围栏/缩进)、HTML 块、hr、脚注定义、引用式链接定义;HTML 块不再伪装成 code(渲染按 html 原样)。
3. **渲染**:同 group 的块合并为一个 md 片段渲染;对照视图按块配对(整列表对整列表)。
4. **结构签名校验**(新增,替代仅 URL + ``` 计数):标题级、列表(有序/起始号/项数/层级/松散/任务)、表格(列×行)、代码块数、行内码集合、URL 集合、引用/hr/HTML/脚注计数。不一致 → **带差异说明自动重译该块一次** → 仍不一致则保留译文并标「格式可能有误」,一键重译。
5. **纯文本粘贴**:按 md 语法密度自动判定;判为纯文本时段内单换行保留为硬换行、行首 `#` `>` `1.` `-` 转义;输入区提供「Markdown / 纯文本」小开关可改判。
6. **协议转义**:源文中的 `<s` `</s` `<t` `</t` 发送前转义为 `&lt;…`、回收后还原(原型往返一致)。
7. **temperature**:默认 **0.3**,服务商详情可覆盖;DeepSeek 官方建议翻译用 1.3,实现期以结构签名失败率对比两档后再定稿(未实测)。

验收:样例集 10/10 拼回结构一致;损伤集 10/10 检出;真实模型下签名失败率作为工单 01 / 实现期指标记录。
