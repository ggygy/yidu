# 02: 语言识别方案调研

Type: research (AFK)
Status: resolved
Blocked by: —

## Question

当前 `detectDir()`(`app/src/languages.ts:53-66`)单字符即判、代码/URL 计入拉丁字母、纯汉字日文判成中文、法/德/西重音规则重叠。应换成什么方案?比较 Rust `whatlang` / `lingua-rs`(及体积、速度、短文本准确率)与改良启发式(先剔除代码块/行内码/URL/标识符、按比例而非单字符、汉字-假名日中判别、置信度阈值),给出在短文本、中英混排技术文、纯汉字日文、带重音的英文借词上的实测准确率,并推荐方案与识别应放前端还是 Rust 侧。

## Answer

推荐**改良启发式 v2**:纯 TS、零依赖,**放在前端**,替换 `detectDir`,改为返回 `{lang, conf}`。Rust 协议不用改。

做法:先去掉代码块、行内码、URL、路径、标识符;再按加权比例判主脚本,不再出现一个字就定语种。中日判别看假名比例,引号内的假名不计;纯汉字时用 JIS 第一水准里的日本专用字形和简繁混用规则判断。拉丁语种用功能词加封顶的变音符权重。

实测 106 条标注样本(含两组留出集):

- 目标语正确率 75% → 95%,源语言正确率 46% → 91%。
- 每次调用约 3 µs,字表约 3.6 KB。
- franc-min 和 eld 先去噪后,目标语正确率为 85%–92%,体积多 46–440 KB gzip,目标语正确率也没有超过 v2。

whatlang 和 lingua-rs 没有在本机实测:没有 Rust 工具链,crates.io 被拦截。按上游报告和源码,两者对纯汉字日文都判成中文,也不处理代码混排;lingua 的 8 语模型还要约 24 MB。因此不选。

置信度阈值:`conf < 0.6`(实测全是短拉丁文本,目标语都正确)时照常发送,徽标显示「?」并支持一键改方向。纯汉字短文本应降低置信度并给出「可能是日文」的切换。

已知残留:不含日本专用字形的纯汉字日文(如 `株式会社`)仍会判成中文。
