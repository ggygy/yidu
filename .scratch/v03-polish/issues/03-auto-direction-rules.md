# 03: 自动方向的产品规则

Type: grilling
Status: resolved
Assignee: wangjunzhou (claimed 2026-11-17)
Blocked by: 02

## Question

在 02 选定的识别方案上,自动方向的产品规则是什么:目标语如何决定(固定母语中文 + 中文源→英?可配置母语?);低置信或识别结果与上次不同时的 UI(如「检测为 日→中」chip 一键改、是否记忆手改);prompt 中源语言写法(低置信时不写死源语言);快捷窗与主窗方向是否共享、如何同步。

## Answer

(2026-11-17 grilling,用户全部采纳推荐)

1. **目标语 = 母语 + 第二语言**:设置新增「母语」(默认中文)与「第二语言」(默认英语)。自动模式下,源语言 = 母语 → 译成第二语言;否则 → 译成母语。默认值与 v0.2 行为一致。
2. **识别**:采用工单 02 的前端启发式 v2,`detectLang(text) → {lang, conf}`;**整篇一个方向**(按全文主导语言,已是目标语的块由模型原样保留),不做逐块方向。
3. **低置信(conf < 0.6)照发不打断**:方向弹出按钮显示「自动 · 中 → EN ?」;纯汉字、≤8 字且无中文虚词无日本信号时置信降为 0.5,并在弹出菜单首项给出「可能是日文 → 改为 日 → 中 重译」。
4. **手改只管这一次**:在弹出按钮里改方向 = 用该方向重译当前文本,模式仍保持「自动」;下次输入重新识别。要固定方向请在弹出菜单显式选具体方向(退出自动)。
5. **Prompt 源语言**:conf ≥ 0.6 写明「{from} → {to}」;conf < 0.6 只写「translate into {to}」,不写源语言,避免错误源语误导模型(需 `prompt.rs` 增加「未知源」编码,如 `?2zh`)。
6. **双窗共享一个方向设置**:快捷窗与主窗共用 `prefs.direction`(含 auto),任一侧切换经 `prefs-changed` 同步(修 A 类缺陷:快捷窗不广播)。

验收:106 条样本目标方向 ≥ 95%;低置信徽标与「可能是日文」入口可见;改向重译不改变 auto 状态;两窗切换 1 帧内同步。
